# 可靠文章搜索设计

## 问题

当前搜索完全依赖构建后才生成的 `/pagefind/` 文件。`pnpm dev` 不运行 Pagefind 后处理，因此模块加载失败，插件却将失败降级为空结果，用户只能看到误导性的 “No Results”。生产环境中 Pagefind 还是异步加载，用户在加载完成前输入存在调用竞态。

## 目标

- 本地开发模式和生产构建预览均可搜索文章。
- 生产环境继续使用 Pagefind 正文全文索引。
- Pagefind 不可用时仍能搜索文章标题、描述和标签。
- 明确区分初始、加载、无结果和错误状态。
- 防止快速输入时旧查询覆盖新查询。

## 数据与架构

搜索页在 Astro 服务端调用 `getPosts()`，把非草稿文章投影成轻量客户端索引：

- `title`
- `description`
- `tags`
- `url`

生产环境优先等待 Pagefind 模块加载并使用其全文结果。开发环境，或 Pagefind 加载失败时，自动使用轻量文章索引。两种搜索源归一化成相同的结果结构，由同一个渲染流程展示。

本地匹配拆成无 DOM 的纯函数：查询按空白拆分为多个关键词，大小写不敏感；每个关键词必须至少命中标题、描述或标签之一。排序优先级为标题命中、标签命中、描述命中，最后保持文章原有的发布日期倒序。

## 交互状态

- `idle`：输入为空，显示“输入关键词搜索文章”。
- `loading`：等待搜索源或查询结果，显示“正在搜索…”。
- `results`：显示结果数量、标题与摘要。
- `empty`：查询完成但无结果，显示“没有找到相关文章”。
- `error`：两个搜索源均不可用时显示明确失败提示，不伪装成零结果。

输入使用 300ms 防抖。每次查询生成递增序号，只有最新序号可以更新界面，从而丢弃过期异步结果。清空按钮会取消当前展示并恢复 `idle` 状态。

状态标题使用 `aria-live="polite"`，搜索框提供中文可访问标签。渲染使用 DOM API 和 `textContent`，避免把文章元数据直接拼入 HTML。

## 范围

### 修改

- `src/pages/search.astro`：提供本地索引、搜索状态与统一渲染。
- `src/plugins/PagefindPlugin.astro`：暴露可等待的加载 Promise，并保留真实失败状态。
- `src/env.d.ts`：补全 Pagefind 与加载 Promise 类型。
- 新增搜索纯函数模块及对应测试。
- `package.json`：增加最小测试脚本和测试运行依赖，仅在项目当前没有测试框架时添加。

### 不修改

- Pagefind 构建及 `postbuild` 索引流程。
- 文章内容集合 schema。
- 搜索范围，仍只包含非草稿文章。
- 文章详情正文的 Pagefind 标记。

## 验证

1. 纯函数测试覆盖空查询、多关键词、大小写、标签匹配与排序。
2. `pnpm build` 成功，并确认 Pagefind 索引生成。
3. 浏览器在 `pnpm dev` 下搜索标题、描述或标签可返回文章。
4. 浏览器在生产 preview 下搜索正文关键词可返回 Pagefind 结果。
5. 快速连续输入只展示最后一次查询；清空恢复初始状态；无匹配显示中文空状态。
