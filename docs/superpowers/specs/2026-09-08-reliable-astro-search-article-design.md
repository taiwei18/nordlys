# Astro 搜索功能复盘文章设计

## 目标

写一篇面向前端开发者的中文实战复盘，解释本站搜索为何在开发模式失效，以及最终如何用 Pagefind 与本地文章索引解决问题。文章需要保留真实排查过程和技术取舍，避免写成改动清单或说明书。

## 标题与定位

暂定标题：《搜索没有报错，为什么就是搜不到文章？》

文章使用第一人称，读者应能跟随现象、证据、根因、方案和验证完成一次完整排查。技术深度以能复用思路为准，不逐行解释所有实现。

## 结构

1. 从 `pnpm dev` 中始终显示 “No Results” 的现象开篇。
2. 对比生产预览中同一关键词返回 3 篇文章，确认文章内容和 Pagefind 本身没有损坏。
3. 解释 Pagefind 在静态构建后生成索引，开发服务器没有 `/pagefind/` 产物；旧代码又把加载失败伪装成空结果。
4. 介绍双搜索源：生产使用 Pagefind 搜正文，开发或加载失败时使用服务端生成的轻量文章索引。
5. 说明异步加载 Promise、300ms 防抖和请求序号分别解决什么问题。
6. 说明通过 `type:post` 过滤器避免时间轴等页面混入文章搜索。
7. 给出浏览器和构建验证结果，并谈清楚本地降级不搜正文这一有意取舍。

## 代码与事实

正文只展示能支撑叙事的关键片段：本地搜索数据投影、可等待的 Pagefind Promise、带过滤器的查询，以及请求序号检查。代码与当前实现保持一致，不虚构 API 或结果。

验证数据：

- Vitest 4 个测试全部通过。
- Astro 构建生成 19 个页面。
- Pagefind 索引 4 个页面、1060 个词和 1 个过滤器。
- 开发模式搜索“小程序”返回 2 篇文章。
- 生产预览搜索正文词“招商visa卡”返回 1 篇文章。

## 写作风格

全文约 1800～2500 字。沿用站内 Markdown frontmatter 和分节方式，但减少机械编号、粗体和列表。使用自然长短句，允许具体判断和简短的第一人称反应。避免宣传话术、空泛意义、三段式套话、否定式排比、频繁破折号和公式化总结。

文章完成后按照 `humanizer-zh` 复写：扫描 AI 高频词、填充短语、刻意排比、同义词循环、模糊归因和“金句”式收尾；保留技术事实和作者语气。
